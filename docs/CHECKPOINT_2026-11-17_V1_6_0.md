## Proteções obrigatórias

1. Nunca reescrever a branch de segurança nem forçar push.
2. Toda evolução começa em branch `feat/*` a partir da main atual; usar PR com checks obrigatórios.
3. Alterar `src/`, `index.html`, `sw.js`, `tools/build_standalone.py` e `JOGAR-OFFLINE.html` de modo sincronizado quando novas dependências forem adicionadas.
4. Executar `npm test`, testes do HTML independente e fluxos de GitHub Actions antes do merge.
5. Manter `localStorage` compatível e nunca perder estrelas, cartas ou upgrades em atualizações; testar saves legados.
6. Cutscenes precisam ser puláveis, repetíveis via Histórias, e nunca avançar/destravar fase por si.
7. Capítulos 1–3 não sofrerão reequilíbrio involuntário durante as mudanças narrativas e gráficas.
8. Validar navegação, pausa, controle por mouse/toque, opção de reduzir movimento e PWA offline.
9. Se 3D falhar, usar fallback 2D; não mudar colisões/grade para apresentação gráfica.
10. Registrar cada marco no `CHANGELOG.md` e no plano de evolução abaixo.

## Como voltar à versão exata

Para inspecionar o checkpoint localmente:

```bash
git fetch origin
git switch -c inspecao-v1.6.0 origin/checkpoint/v1.6.0-2026-11-17-antes-campanha-2p5d

```

**Não** usar `git reset --hard` na `main` publicada nem apagar saves dos jogadores. Para reverter uma mudança, preferir `git revert` no PR/commit problemático ou restaurar arquivos específicos do commit de referência em um novo PR, mantendo o histórico.
